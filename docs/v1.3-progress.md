# v1.3 进度总览（2026-10-24）

一天之内从"能刷"到"能用"。本文是博客第十三章的仓库对应版，两处保持一致。

## 已完成（全部真机验证）

### 有线硬件加速（PPE）— 已验证 ≥395 Mbps

- **机制**：`zx279128s-ppe.c` 从基线就有完整的硬件流卸载（分类器规则/流表/trap 真编程），v1.3 补的只是
  `kmod-nft-offload` + `flow_offloading=1`（含 hw）这两块拼图。
- **验证三重铁证**（OPPO 商城 CDN、32 线程浏览器原生 fetch）：
  1. **395 Mbps 持续**（停止时仍在上升，真实上限更高）；
  2. **CPU 占用 7%**（双核合计，峰值 22%）；
  3. **WAN 软件计数器纹丝不动**——PPE 直转的包不过 CPU 网络栈，
     `/proc/net/dev` 看不到它们（这也是为什么不能用 WAN 计数器测 PPE 速率）。
- **"200M 上限"是假象**：腾讯 CDN 对单 IP 限速 ~200M；换 OPPO CDN 立刻 395M。
  误判过程与教训记入博客 13.3。
- **WiFi 客户端例外**：流入口必须是交换芯片自己的口（lan1-3/wan），WiFi 流被架构性
  拒绝（`ppe_add_skip`）→ CPU 软件路径 ~200M。原厂 WiFi 千兆靠 IDM/NPP 私有直通
  （4.1 内核二进制，不可用于 6.18）。

### Wi-Fi

- 开机自动加载（START=95 + 25s 延迟；时序方案来自 tigaotg 的交接 PR#1）。
- 首启 SSID 从原厂 tag 分区读取本机出厂名（tag 里 "X" 与 "X-5G" 成对出现即出厂双频名）。
- **首启开放网络 + 无 root 密码**（用户自行设置，console 打印安全提醒）。
- 5G 发射功率 20 → **23 dBm**（country 00 全频封 20；`e2631-wifi-ap` 两条路径都写 CN）。
- 校准数据一直从原厂 wifi 分区运行时读取（`11-mt76-caldata`），无烘焙副本。
