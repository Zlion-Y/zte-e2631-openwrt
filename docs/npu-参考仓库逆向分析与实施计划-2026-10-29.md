# npu 分支：原厂有线/无线全栈逆向与重写计划（2026-10-29）

> 方向修正：本文件取代同日早先的“混合路线”版本。早先建议保留 mt76/mac80211 +
> `nf_flow_table` 的方案作废。`npu` 的目标改为：**以原厂 4.1.25 的二进制、配置、
> 固件为唯一行为规范，在 6.18 上重写一套 ZX279128S 有线 + MT7916 无线的私有栈。**
>
> 分支：`npu` 从 `main` 的 `251ac0c`（v1.8.0）创建；`main`、`ffe`、`ffe-full`
> 一行不改。仓库里没有 `ffu` 分支，本文按 `ffe` / `ffe-full` 理解。

## 0. 一句话

**不再把开源驱动/加速栈当数据面。** 有线按原厂 `switch.ko + tm.ko + plat +
内建 FFE + idmfdb.ko` 的职责重写；无线按原厂 `mt7916.ko`（CSP_WLAN，MTK 私有
AP SDK）重写 host driver + AP 管理 + QM/IDM 对接。Linux 内核通用子系统保留，
但所有 ZX279128S/MT7916 相关的设备驱动、加速控制面、无线数据面全部自研。

## 0.1 运行态基线（2026-10-29 已取）

已在 192.168.5.3 上完成三轮只读取证（详见
`docs/npu/01-vendor-runtime-baseline-2026-10-29.md`）：

- 模块栈：`plat ← tm ← {switch, mt7916}`，`switch ← idmfdb`；`mt7916` 引用计数 4。
- FFE v3.6.6 运行中：6 条流（TCP 2 / UDP 3 + 1），`npu:1`；WiFi 流
  `eth0 → nbif0 → wlan0` 与反向 `wlan0 → nbif0 → eth0` 都在同一张表里。
- IDM：`idm1` 承载 AP（wlan0/5g0…），`idm0` 承载 APCLI；`/proc/idm/stat` 有
  完整 push/pop 计数，并已见 `push_failed[2]=566`、`stack_empty[2]=3224`。
- 无线：`wlan0/5g0` AP + `wlan3/5g3` MESH + 4 个空 VAP + 2 个 APCLI；
  没有 `hostapd`/`wpa_supplicant`，由 `cspd/idm_service/multiapd` + `Rtmp*Task` 管理。
- `/proc/iomem` 没有 NPP/IDM/TM/PP 的保留区；不能假设 DT reserved-memory。
- `/proc/kallsyms` 可读，已拿到 `ffe_* / wlan_* / nbif_* / wb_* / tm_* / mt7916`
  的本次 build 精确地址；重写时可直接作为函数级锚点。
- `npu_cap` 已给出 IPv4/IPv6/DS-Lite/raw/multicast 的 NPU 能力与 per-feature
  pps/层能力；当前 v6 计数 0 只是没流量，**IPv6 不是硬件限制**。
- `iwpriv` 列出 16 个私有 ioctl（`set/show/phystate/get_site_survey/...`），
  这是原厂控制面；重写要么等价实现，要么定义自己的 netlink/proc 接口。

可行性快照见 `docs/npu/02-feasibility-2026-10-29.md`：有线高置信（8-12 周）、
FFE 中高置信（4-6 周）、MT7916 最小 AP 中低置信（4-6 个月，先过 G3）、
原厂全功能无线低置信（不建议首版）。

## 1. “抛弃开源内容”的边界（先钉死，否则会做成四不像）

| 层 | 处理 | 说明 |
|---|---|---|
| Linux 6.18 内核本体 | **保留** | 原厂自己也是 Linux 4.1.25；重写内核不现实，也不是“逆向原厂” |
| 通用子系统：netdev、bridge、conntrack、PCIe、SPI、GPIO、DMA | **保留** | 原厂同样使用这些；它们是状态源/基础设施，不是厂商私有加速实现 |
| 启动/刷机/槽位/打包 | **保留** | `e2631-fwslot`、打包器、U-Boot 交互与本次驱动重写正交 |
| ghahramani/OpenWrt 的 `zx279128s-eth`、`zx279128s-ppe` | **删除/替换** | 不再作为有线数据面 |
| `nf_flow_table` 硬件卸载 | **不再作为数据面** | 改用自研 FFE 控制面；conntrack 只作为状态源/联动 |
| `mt76` / `mac80211` / `cfg80211` | **删除/替换** | 原厂是 CSP_WLAN 私有栈，不使用 cfg80211 |
| `hostapd` / `wpa_supplicant` | **不作为无线控制面** | 原厂 AP 管理在私有驱动/固件内；我们写最小自研管理面 |
| ZX279128S 有线驱动族 | **自研** | gmac/switch/PPE/FFE/NPU/IDM/TM/BMU/QMG/SCH/RED/idmfdb |
| MT7916 host driver + AP 管理 | **自研** | PCIe、固件下载、MCU、WFDMA、TXD/RXD、BSS/安全/关联、QM/IDM |
| OpenWrt 用户态 | **先只保留 rootfs/构建** | netifd/fw4/LuCI 不进入新数据面；WiFi 管理用自研 daemon。若要求连 OpenWrt 也不用，另开独立 rootfs/init（见 §9 决策） |

**为什么保留 Linux 通用子系统**：原厂 4.1.25 本身就是 Linux；它的 FFE/conntrack、
bridge、netdev、PCIe 都建立在内核通用层上。所谓“全部完整逆向原厂”，指的是
**不引入任何第三方开源设备驱动/加速栈**，不是把 Linux 重写一遍。否则连
TCP/IP、DMA、PCIe 都要重写，工程上没有意义。

## 2. 参考仓库能给我们什么、不能给什么

### 2.1 三个仓库的分工

| 仓库 | 分支/HEAD | 角色 | 关键内容 |
|---|---|---|---|
| `cnjn/ZXSLC_SR1010` | `main` `e62f7ef` | 证据源 | 原厂全片 dump 的 firstboot/U-Boot/rootfs/config 加密体系、密钥、重打包 |
| `cnjn/linux-mainline-zte-zxslc-sr1010` | `codex/sr1010-mainline` `e1efdee` | 实现层 | 122 个提交；`drivers/net/ethernet/zte/` 21,261 行自研驱动 + DSA/PHY/SerDes |
| `cnjn/immortalwrt` | `sr1010-zx279133` `1b50aaf` | 交付层 | `target/linux/zte`、DTS/config、mkfw、`zte-fwslot`、首启默认值 |

### 2.2 可复用的逆向方法

1. **只读审计先行**：RTL8372N/ZX279051/XPCS 的只读 ID/状态审计驱动
   （`Documentation/devicetree/bindings/net/zte,sr1010-*-audit.yaml`、
   `soc/zte/zx279133-xpcs-nppt-audit.yaml`）。
2. **函数级转写**：每个常量指回原厂函数，例如
   `zx279133-idm.c:1368-1443` 的 `idm_init()` 寄存器镜像来自 `plat_132.ko`
   反汇编 + `kernel-2b5.elf` 数据；`zx279133-np.c:598-687` 的 WANID 来自
   `np.ko` 的 `index | direction << 4` 语义；`zx279133-offload.c:337,622,684`
   来自 `fast_table_write()/fast_hashinfo_set()`。
3. **指纹门**：PPU microcode 必须匹配大小 103456 + CRC32 `0xef1d7647`，
   否则回退原生队列（`zx279133-np.c:1998-2008`）。
4. **分级验证**：16 个功能阶段 + 每阶段 `validation/incremental/000N-validation.txt`；
   WAN 2.35 Gbit/s、LAN 939 Mbit/s（`0008-validation.txt:45`）。
5. **证据不足就停**：参考实现把 IPv6 提取规则、microcode 授权、寄存器镜像
   provenance 都明确标成未解决，上游状态 **NO-GO**。

### 2.3 不能照抄的部分

- **无线没有实现可抄**。SR1010 是纯有线机型：DTS/config/驱动里没有 WLAN/PCIe
  WiFi 节点，只有 IDM 的 `companion/Wi-Fi path` 注释。E2631 的 MT7916 私有栈
  必须自己逆向。
- 参考实现的有线控制面仍然用了 `nf_flow_table`/`tc`（`zx279133-offload.c:1485-1545`）。
  我们这次要更进一步：**连控制面也按原厂 FFE 重写**，不再依赖 nf_flow_table
  的硬件卸载路径。
- 参考的寄存器偏移/队列模型属于 ZX279133，不是 ZX279128S：
  NPPT 基址 `0x19000000` vs `0x921c0000`；IDM 偏移 `+0x280000` vs `+0x8000`；
  24 RX/16 CPU RX/4 TX vs E2631 的 2×idm netdev、RX A/B 2048、TX 1024。
  所有偏移必须按 E2631 原厂重新推导。

## 4. 目标架构（vendor-native）

### 4.1 有线

```
用户/协议栈
  │  netdev（SBRG 5 口 + 4×GE PHY；WAN/LAN 角色）
  ▼
zx279128s-switch        SBRG MAC/VLAN/端口；L3 会话入口
  │
  ├─ 首包/慢路径 ──► zx-ffe（学习/协议层/NPU 插件/conntrack 联动）
  │                     │
  │                     ▼
  │                  zx-ppe（PP/CLA/PM/SBRG/ADM/DPA 表编程）
  │
  └─ 命中 ──► PP 分类器 → PM 重写 → egress（LAN/WAN/IDM 伪端口）
                                   │
                                   ▼
                              zx-idm（RX/TX ring、NAPI、page_pool）
                                   │
                                   ▼
                              WiFi host driver / QM
```

- **不再有** `nf_flow_table` 硬件卸载、`TC_SETUP_BLOCK/FT`、ghahramani 的
  `zx279128s-eth/ppe`。
- **conntrack** 保留：原厂 FFE 也用 conntrack 做状态联动；但流表由 FFE 自己维护。
- **idmfdb** 等价物：IDM 慢路径 MAC FDB/转发，自己写。
- **proc/sysfs**：复刻原厂 `/proc/zte/sys/ffe/cmd` 语义（或等价 netlink），
  作为我们自己的控制面，不依赖 vendor 用户态。

### 4.2 无线

```
用户/管理面（自研 wlanmgr）
  │  BSS/SSID/安全/关联/密钥
  ▼
csp_wlan host driver（自研）
  ├─ PCIe probe / BAR / MSI/INTx / DMA
  ├─ 固件下载：ROM patch → WM → WA；EEPROM/caldata；DBDC
  ├─ MCU 命令/事件（Andes）：BSS、信道、速率、PP mbss、统计
  ├─ WFDMA TX/RX ring、TXD/RXD、BA/聚合、重传（固件侧）
  └─ QM / IDM 对接：tx_pkt_classification、idm_skb_stack 等价物
  ▼
MT7916 固件（vendor blob：WIFI_RAM_CODE / WACPU / patch）
```

- **不再有** `mt76`、`mac80211`、`cfg80211`、`hostapd`、`wpa_supplicant`。
- **AP 管理**：BSS 创建/删除、SSID、WPA2/WPA3、关联/去关联、密钥安装、
  4 地址、多播、WMM；先做最小单 SSID/WPA2/双频，再做多 SSID/160M/DBDC。
- **加速**：下行 PP 重写 → QM → 无线 TXD；上行无线 RX → IDM → PP。
  原厂 `write_tmac_info_offload_pkt`、`tx_pkt_classification`、`pp_mbss_init`
  的行为要逐函数还原。

### 4.3 用户态

- 最小 `wlanmgr`：读 `/etc/wireless/mt7916/*.dat` 兼容格式，配置 BSS/安全；
  提供 ubus/netlink 或 proc 接口。
- 最小 `ffectl`：读 FFE 状态、开关、统计；兼容原厂 `ffe/cmd` 语义。
- 网络配置：先保留 OpenWrt 的 netifd/fw4 仅用于 LAN/WAN/DHCP/NAT；如果
  “连 OpenWrt 也不用”，则另写最小 init + 网络管理（见 §9）。

## 5. 分阶段实施

### P0 — 证据冻结与合法性（1-2 周，部分已做）

- **[已做] 运行态只读取证**：模块栈、FFE、IDM/FDB、WiFi、PCIe、iomem、kallsyms，
  见 `docs/npu/01-vendor-runtime-baseline-2026-10-29.md`。
- 全量清点 vendor 模块/固件/配置/内核；SHA256；建立 `docs/npu/evidence-index.md`。
- 只读拉取原厂 rootfs 中与 WiFi/FFE 相关的配置与脚本（`cspd` 若可得），
  不做任何写入。
- 反汇编环境：capstone/arm objdump；对 `mt7916.ko`、`plat`、`tm`、`switch`、
  `kernel1.bin` 建立符号/调用图。
- 法律/授权评估：vendor 固件 blob、MTK 私有驱动的再分发边界；GPL 索取路径。
- **门禁**：关键物料无缺失；每个后续写寄存器都能指回证据；授权风险有书面结论。

### P1 — 有线寄存器/表模型（2-3 周）

- 以运行态基线为第一组 golden reference（`idm_map`、FFE 流键/计数、IDM 计数）。
- 逐项 diff E2631 vs 参考：NPP/IDM/TM/PP/SBRG/CLA/PM/BMU/SE/SMAC。
- 只读审计模块（仅 ioremap + read）先跑通；钉死 IDM 五个冲突点。
- 产出 `docs/npu/register-diff.md` + `re/npu/regtables/`。
- **门禁**：所有写操作有原厂见证；未知项明确列出；只读基线落盘。

### P2 — 有线驱动族（4-6 周）

- 新驱动：`zxnpu-core`、`zxnpu-tm`、`zxnpu-ppe`、`zxnpu-idm`、`zxnpu-switch`、
  `zxnpu-idmfdb`；不引用 ghahramani 代码。
- 顺序：MMIO/时钟/IRQ → TM/BMU → PP/CLA/PM → switch/SBRG → IDM → 收发。
- **门禁**：1G 双向线速；单口 ping/大流量；无 Oops/watchdog；驱动符号表里
  没有开源替代实现的依赖。

### P3 — FFE 控制面（4-6 周）

- 按 `kernel1.bin` 符号/反汇编重写：`ffe_flow_key`、`ffe_learn_skb`、
  协议层（eth/vlan/pppoe/ipv4/udp/tcp/ipv6/multicast）、`ffe_npu_*` 插件、
  `ffe_flush_flow_by_conntrack`、proc 语义。
- 以运行态 `npu_cap` 为能力表：IPv4/IPv6/DS-Lite/raw/multicast 都要实现，
  不再按“v6 只能 CPU”设计；per-feature pps/层能力按 `npu_cap` 建模。
- 与 P2 的 PPE/CLA/PM 表对接；不用 `nf_flow_table` 硬件卸载。
- **门禁**：IPv4/IPv6/PPPoE 流学习+卸载+删除+统计；conntrack 联动；
  组播 flush；1G 线速；24h 稳定。

### P4 — 无线固件启动（3-5 周，关键 go/no-go，判据见 `02-feasibility` 的 G3）

- 自研 host driver 的 PCIe probe、BAR、DMA、固件下载（patch/WM/WA）、
  EEPROM/caldata、MCU 命令/事件、最小 RX/TX ring。
- 目标不是 AP，而是：**自研驱动能把 vendor 固件拉起来，并能收发一帧**。
- **门禁**：固件版本/状态可读；RX/TX 各一帧成功；无 mac80211/cfg80211 依赖。
  如果这一步过不了，后续全栈无线的可行性要重新评估。

### P5 — 无线 AP 最小闭环（6-10 周）

- BSS/SSID/信道/带宽、WPA2、关联/去关联、密钥、TX/RX、BA/聚合、速率控制
  （尽量交给固件）。
- 最小 `wlanmgr`；先单 SSID、单频段，再双频/多 SSID。
- **门禁**：手机可关联、WPA2 可过、ping/吞吐正常、1h 不死；无 hostapd。

### P6 — 无线加速（4-8 周）

- QM/IDM 对接：`tx_pkt_classification`、TXD 预构建、`pp_mbss_init`、
  `idm_skb_stack` 等价物；下行 PP 重写 → QM → 无线；上行无线 → IDM → PP。
- **门禁**：有线↔无线双向硬件路径；CPU 明显下降；关联/ARP/多播正常；
  逐流可回退；24h 稳定。

### P7 — 集成与交付（2-4 周）

- 用户态、配置、默认值、恢复路径；OpenWrt 只保留 rootfs/构建（或按决策替换）。
- 全链路刷机/回退/双槽；Release 说明写清“已验证/未验证”。
- **门禁**：端到端验收；无开源数据面依赖证明；可回退原厂。

**工程量口径**：有线 P1-P3 约 10-15 周；无线 P4-P6 约 13-23 周；P0/P7 另计。
不承诺总工期，按门禁推进。无线是关键路径，建议与有线并行启动 P0/P4 的证据工作。

## 6. 验证方式

### 6.1 “无开源数据面”证明

- 镜像/模块符号表：不得出现 `mt76`、`mac80211`、`cfg80211`、`hostapd`、
  `wpa_supplicant`、`nf_flow_offload` 的依赖；`modinfo`/`nm`/`readelf` 见证。
- 构建 manifest：不安装 `kmod-mt76*`、`kmod-mac80211`、`hostapd`、`wpad`。
- 运行时：`lsmod`、`/proc/modules`、`/sys/module` 只看到自研模块。
- 代码审查：新驱动不 include 第三方驱动头文件，不调用其导出符号。

### 6.2 离线 golden vector

- 每个键/哈希/表项/描述符构造函数至少 3 组向量：原厂反汇编常量、参考实现
  交叉检查（仅参考）、手算期望。
- 单元测试放 `tests/npu/`，不依赖真机；失败阻断构建。

### 6.3 只读真机审计

- 只读模块/脚本；不写、不 reset、不加载原厂 ko。
- 采集：寄存器、计数器、表项、`/proc/interrupts`、`/proc/net/dev`。
  原厂 BusyBox **没有 `dmesg/head/tail`**；脚本用 `cat/sed/grep`，不要依赖这些 applet。
- 与 P1 register-diff 对照；不一致先查清，不带病写代码。

### 6.4 真机 A/B

| 维度 | 取值 |
|---|---|
| 有线 | v4/v6/PPPoE/组播/双向/小包/MTU 边界 |
| 无线 | 单 SSID/双频/多 SSID/WPA2/WPA3/160M/关联/断开 |
| 加速 | off / 有线硬件 / 无线硬件 / 双向硬件 |
| 观测 | 吞吐、CPU、FFE 流数、PPE/IDM 计数、conntrack、ARP/NDP、dmesg |
| 时长 | 每项 ≥10 分钟；关键项 1-24 小时 |

一次开机只动一个变量；原厂槽和 failsafe 始终保留；不裸跑原厂二进制。

## 7. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| `mt7916.ko` 5.6 MB / 7760 函数，无源码 | 无线重写是最大不确定项 | P4 先做“固件启动 + 一帧收发”go/no-go；不要先写 AP |
| 固件接口/命令未文档化 | MCU 命令错会导致固件挂死 | 逐条对照原厂驱动；先只读/回环；一次一个命令 |
| 有线寄存器偏移/队列模型与参考不同 | 直接移植会静默丢包 | P1 强制 diff + 只读基线 |
| IDM 语义冲突 | 环失步/缓冲泄漏 | 只读实测 + 单环最小实验 + 计数器断言 |
| IDM skb 栈压力 | `push_failed`/`stack_empty` 导致丢包 | 运行态已见 566/3224；重写做水位、重填、丢包计数与告警 |
| 32 位 DMA/缓存别名 | 地址截断/写错内存 | 复用现有 32 位掩码/别名处理；边界检查 |
| 硬件 NAT 只写一个源 MAC | LAN/WAN 不同 MAC 时全拒 | 先测 E2631；必要时要求同 MAC |
| microcode/固件授权 | 不能合法再分发 | P0 法律评估；必要时不分发 blob，只做本地构建 |
| 用户态重写范围过大 | 工期失控 | 先保留 OpenWrt 仅作 rootfs；数据面自研；逐步替换 |
| 实机实验耗电/变砖 | 设备不可用 | 原厂槽不动；failsafe；一次一个变量；后台任务管好 |

**回退**：`npu` 不合并、不默认发布；任何实验失败可回到 `main` 的 v1.8.0；
原厂槽始终保留；刷机走 `e2631-fwslot`。

## 9. 需要用户确认

1. **用户态边界**：保留 OpenWrt 仅作 rootfs/构建、数据面与控制面自研（推荐）；
   还是连 OpenWrt/netifd/fw4/LuCI 也全部去掉，做独立 rootfs/init？
2. **无线功能范围**：先做“最小 AP”（单/双 SSID、WPA2、双频、基本吞吐、加速），
   还是一开始就追原厂全功能（WPA3、160M、多 SSID、mesh、漫游、WMM、DBDC SKU）？
   前者可在 P5/P6 验收，后者工期和风险都显著增加。
3. **实机窗口**：P1 只读审计、P4 固件启动、P5/P6 AP/加速都需要设备时间；
   在你放行前，所有工作停在离线/静态验证。
