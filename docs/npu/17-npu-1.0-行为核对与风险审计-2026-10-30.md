## 1. 原厂活体证据（[实测]）

1. **模块栈**：`xdpi`(882 KB) ← `plat_zxylzb_9128S` ← `tm` ← {`switch`, `mt7916`}，

2. **FFE 控制面全图** `/proc/zte/sys/ffe/`：`cmd`(用法帮助)、`ffeinfo`、
   八协议状态文件（ipv4/ipv6 × tcp/udp/mc/raw）、`hash/<proto>_hash`×8、
   `npu/<proto>_npu`×8 + `npu_cap` + `npufilter`、`scripts/`×21（acc_thresh、
   del、ffe、flowcnt、icmp_acc、layer_enable、mcastdebug、no_delete、npu、
   npudd、npuretry、pps、rps_cpu_map、rps_tx_queue_max、show、timer…）、
   `sharedata/{ffe_cmd,ffe_path}`、`learnlist`。
3. **ffeinfo 活体**：v3.6.6，enable:1，max flow 28136，curr 522，
   ipv4_udp 155/155、ipv4_tcp 91/91、**ipv6_udp 154/154、ipv6_tcp 122/122
   —— 全部 npu:1**；slowpathcnt 25.9 万 vs 总 rx 281 万（≈9% 慢路径）；
   RPS cpu_cnt 2 / cpu_map 3 / tx_queue_max 1024；npuinfo createfail:1。
4. **ipv6_tcp 表活体**：`enable:2, flows:116, npu_flows:116, slot_size:1024`
   ——v6 独立 1024 槽表；流条目 `npu:1 1`（双向 NPU）、`attr:0003`、
   `cmd:[tcp_skip+0x0/0x3c]->[ipv6_skip+0x0/0x3c]->[eth_skip+0x0/0x3c]`、
   `passed dev:[eth0]->[nbif0]->[wlan5g0]`、retry_left、rps 逐流绑定 cpu0/1。
5. **npu_cap**：flow_feature index[0]=下行（pon0/pon/gpon0/epon0/ptm0 →
   eth*/wlan*）、index[1]=上行（eth*/wlan* → pon/ptm0）；type 编号
   3=ipv4_tcp、4=ipv4_udp、5/6=dslite_tcp/udp、9=ipv6_tcp、10=ipv6_udp；
   每层 layer_cap 位掩码；dslite pps 256、layer3 v4tcp pps 20、frag 位。
   **v6 与 v4 的层能力完全同级**——v6 是一等流类型。
6. **/proc/idm/stat 活体**：push_cnt[0]=1,974,454、push_cnt[2]=2,411,517、
   pop 与 push 差 <1100、push_failed[2]=809、push_failed_res[5]=809、
   stack_empty[2]=3238、skb_stack_full[0]=181、idm_poll_cnt=3,907,936、
   tx_done_total=1,140,146、txtq_err=0。
7. **拓扑与流量**：idm1 RX 2.4 GB（AP 下行主通道）→ nbif0 RX 2.18 GB；
   wlan5g0 TX 2.08 GB；idm0=0（APCLI 空闲）；pon↔eth0 对称 2.6 GB。
8. **kallsyms 锚点**：`npu_drv_{indev_learn,outdev_learn,free_flow,
   lookup_multientry,delete_multivlan,create_multivlan,refresh_flow,
   get_flow_stats,dup_flow,delete_flow,create_flow}` [switch]、

9. **cmd 帮助 = 完整控制面语义**：八协议 `proto 0/1/2`（0=全禁 1=FFE

## 3. 重启/变砖风险审计（重点项）

1. **默认零硬件写入**：本固件所有新代码默认静默——
   `zxnpu_idm.enable=0`（首次寄存器写在 `ip link set zxnpu0 up` 且 enable=1）、
   `zxnpu_ppe.enable=0`（写命令拒）、audit 模块只读、csp-wlan `enable=0` +
   `commit=0` 双门。**刷入后的启动路径 = v1.8.0 已在真机连续验证过的栈**。
2. **ffe 六项根因逐条核对**（zxnpu-idm 源码级）：
   - ① 野指针绑定卡死：不存在——zxnpu0 是独立 netdev，无 mac80211
     setup_tc 路径；
   - ② IDM 寄存器序列：+0x04=TX 基址/+0x08=RX 基址 ✓、NPP
     MASK/INTEN/CFG40|0x300/PPB=128 ✓、CFG00 RMW/CFG10/18/1C/24 ✓、
     DEPTH=0x04000800 ✓；
   - ③ 交付拷出：napi_alloc_skb + skb_put_data 逐帧拷出 ✓（无零拷垃圾）；
   - ④ FFE ops 指针：无此路径（不走 ffe 控制面）；
   - ⑤ rtnl 断言：无桥 FDB 查询；
   - ⑥ 注入钩子：无 mac80211 依赖。
3. **DTS 资源空节点**：npu/audit/idm/ppe 四节点无 reg/clocks/interrupts，
   与 gmac/PPE 驱动不可能冲突。
4. **Kconfig 新符号**：CONFIG_ZX_NPU/AUDIT/IDM/PPE/CSP_WLAN 五个由 apply.sh
   awk 钉死（防 oldconfig 卡死）。
5. **双门禁**：verify_pkg ALL CHECKS PASSED（1 条已知良性 warning）+
   BOOT-READY（release.mjs 内置 verify_img）；裸 zImage 场景被 uImage magic/
   load==ep/ih_dcrc 硬门拦截。
6. **版本与内容核验**：rootfs `/etc/e2631-version` = `OpenWrt npu-1.0`；
   vmlinux 含 `sbrg: vlan` 字符串与 `zxnpu_ppe_driver_init` 符号（System.map）。
7. **无 CRLF**：本轮新增/修改文件全部 LF（file/grep 复核）。
8. **残余风险（如实声明）**：enable=1 之后的运行时行为（IDM 环真实吞吐、
   SBRG 表写入）仍属真机实验范畴，受禁刷约束未验证；但**这些代码路径在默认
   配置下不可达**，不构成重启/变砖风险。原厂槽未动，可随时回退。

## 4. 结论

- npu-1.0 = v1.8.0 数据面 + npu 驱动族（只读/默认关闭）+ zwzzrl sbrg 采纳，
  双门禁全过，启动路径与 v1.8.0 逐字节同源，**无已知的重启/变砖缺陷路径**。
- 原厂行为核对：9/9 项一致或模型吻合；唯一差距（v6 单播 NPU 卸载、xdpi
  DPI 会话）属 P3/P6 未竟项，已列入计划。
