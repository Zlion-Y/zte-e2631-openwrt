# G3.3 设计：Andes MCU 命令通道（2026-10-29）

> 本文只记录已经从 `mt7916.ko` 指令级确认的事实和下一步要解的函数。
> 它不是构建记录；npu-0.9 才会把这些变成代码。

## 1. 已经确认的调用链

```
WfMcuInit (0xAD7B8)
 ├─ WfMcuSysInit (0x146ABC) → chip_fw_init (0x142D3C)
 │    └─ hc_get_chip_ops / hc_get_hif_type（间接调用，未展开）
 ├─ NICLoadRomPatch (0x1DE8CC) ─→ mt_load_patch (0x1D7180)
 │    └─ load_patch_v1 (0x1D5C0C)
 │         ├─ MtCmdPatchSemGet      (0x1CBFEC)
 │         ├─ MtCmdAddressLenReq    (0x1CBDA8)
 │         └─ MtCmdPatchFinishReq   (0x1CC0CC)
 │              └─ AndesAllocCmdMsg → AndesInitCmdMsg →
 │                 AndesAppendCmdMsg → chip_cmd_tx (0x142C70)
 └─ NICLoadFirmware (0x1DE8D0) ─→ mt_load_fw (0x1D7358)
      └─ chip_ops->[0xFA8]/[0xFB0]/[0xFB8]（按 band 下载）
```

`mt_load_fw` 先调用 `chip_ops->[0xC8](priv, 1)`（暂停），再对 band 0/1
分别调用 `[0xFB8](priv, 1|3)`（进入 FWDL 模式），随后 `[0xFA8]`/
`[0xFB0]` 负责分段投递，最后 `chip_ops->[0xC8](priv, 0)`（恢复）。

## 2. Andes 命令消息的内存布局

`AndesAllocCmdMsg(priv, len)` 只是 `hif_mcu_alloc_msg(priv, len, 1)`。
返回对象：

| 偏移 | 类型 | 含义 |
|---|---|---|
| +0 | u16 | 长度（`AndesInitCmdMsg` 从参数低 16 位写入） |
| +2 | u8 | **type**（调用点写 0x10 / 0x05 / 0x07） |
| +3 | u8 | 序号/保留 |
| +4 | u8 | **cmd**（三条 patch 命令都是 0x17） |
| +6 | u16 | 参数高半字 |
| +8 | u16 | 参数 |
| +12 | u32 | 参数 |
| +16 | u32 | 参数 |
| +20 | u16 | `GetRealPortQueueID(type)` 得到的队列号 |
| +23 | u8 | 标志（bit2 = 同步等待；bit1 = 置 3） |
| +32 | skb* | 实际缓冲；payload 从 +24 开始 |

`AndesAppendCmdMsg` 就是 `skb_put(skb, len)` + `memcpy`；因此一条
消息 = skb 头部的 24 字节命令头 + 若干 4 字节 payload。

三条 patch 命令的 payload：

```
SemGet      : type=0x10 cmd=0x17 payload = sem (u32)
AddressLen  : type=0x05 (地址命中 chip_cap+0x12C) 或 0x01, cmd=0x17
              payload = addr (u32), len (u32), arg (u32)
Finish      : type=0x07 cmd=0x17 payload = 空
```

## 3. 固件头与分段

`mt7916_patch_e1_hdr.bin`：

```
0x00 date[16]; 0x10 platform[4]="ALPS"; 0x14 u32; 0x18 u32; 0x1c u32;
0x20 magic 0x11223344; 0x24 addr 0x04000000; 0x28 len?; 0x2c 1;
0x30 0xffff0000
```

`0x04000000` 是 MCU SRAM 基址，patch 的每个 4 KiB 段以
`AddressLenReq` 投递。`WIFI_RAM_CODE_MT7916.bin` 与
`7916_WACPU_RAM_CODE_release.bin` 无头，首字节即 Thumb 代码。

## 4. 还缺的两块（npu-0.9 的输入；§6.5 已闭合大半，见修正注）

1. **WFDMA MCU 环基址/深度寄存器**：`pci_init_txrx_ring_mem`
   （0x1E4A64）与它调用的 `multi_hif_entry_*` 系列；需要把每个
   环的 base/len/cidx/didx 寄存器地址和描述符格式解出来。
2. **`chip_cmd_tx` 的投递**：它决定 skb 走哪个 WFDMA TX 环、如何
   kick。拿到 1 之后，这条链路才能在不依赖 mt76 的情况下工作。

## 5. 判据（沿用 03 文档 G3 门禁）

- 成功：`MtCmdPatchSemGet` 返回 0，`AddressLenReq` 全部返回 0，
  `PatchFinishReq` 后 MCU 事件显示 `MCU Init Done`。
- 失败即停：任一命令超时、WFDMA 不前进、PCIe 错误，都不重试刷写，
  不继续加载 RAM code。

### 6.2 chip_cmd_tx → bufferModeCmdFill（缺口②的一半已闭合）

`chip_cmd_tx`(0x142C70) 全文只是 `bx chip_ops[0xF0]`，且**不清洗 r2**——r2 从
Andes 发送方一路透传（0x94abc 调用点：r0=priv、r1=skb，r2 未显式置值，
是上一条 `AndesAppendCmdMsg(msg, len)` 的 len 遗留）。`bufferModeCmdFill` 语义：

```
msg[0]    = r2 & 0xff
msg[1]    = (r2 >> 8) & 0xff
msg[2..3] = 0（后改写为拷贝字节数）
若 r2 bit0 == 0：到此返回（不拷贝）
idx = r2 bits 2..4；若 idx != (r2>>5) → buflen=1024
否则 buflen = chip_cap+0x106 低 10 位（0 → 1024）
循环：从 *(priv+0x5ED40C) + (idx<<10) + i 逐字节读，写入 msg[4+i]，i=1..buflen
```

**r2 语义未定**：调用点不显式传 r2，"bit0=1 才拷贝"与 len=4 的遗留值矛盾——
要么真正发送路径另有其人（`dbg_ut_wmcu_send` 0x2b8410 值得对照），要么
bufferModeCmdFill 只负责 buffer-mode 帧的填充而发送在别处。**结论：MCU TX
在此 build 是 buffer-mode 而非 WFDMA 描述符环**——这改写 §4 的前提，
G3.3 的"还缺 WFDMA MCU 环"应改为"还缺 buffer-mode 投递通道
（PSE/WM 里 cmd buffer 的 bell 寄存器）"。

### 6.3 hif_set_WFDMA(0x19194C) —— WFDMA 使能开关 [实测-静态]

对 `MAC CR 0x18024208`（band1 镜像 `0x18028208`，在调试条件内同时写）做 RMW：
参数 r6=0 → bit0；r6=1 → bit2(0x4)；r6=2 → bits0|2(0x5)；r7=1 置位 / 0 清位。
与 doc 13 §3 序号 1 的 0x18024208 一致，即 mt76 connac 的 WFDMA0_GLO_CFG 语义
（bit0=WFDMA_EN、bit2=TX DMA EN）。BAR 基址仍走 `hif_ctrl+0x2b0`→+0x688。

### 6.4 pci_init_txrx_ring_mem(0x1E4A64) 主机侧结构 [实测-静态]

这是**环内存初始化**，不是寄存器编程。结构事实（G3.3 建模用）：

- `hif_ctrl+0xa8` = 环组数(u8)，`+0xac` = 组指针数组；
  组 entry：+0x10=RX 环数、+0x11=TX 环数、+0x14=TX 环数组、+0x18=RX 环数组、
  +0x58=环组 id 回填。
- RX 环结构步长 **96B**，TX 环步长 **160B**；环内 +0x14=desc 数(u16)、
  +0x18=desc 数组、+0x1c/0x20=索引、+0x80=标志位（置位时环指针进 hif_ctrl+0x98/+0x4 表）。
- desc 数组元素步长 **36B**：`[0]`=16（大小常数）、`[4]`=当前 VA、`[8]`=末 VA、
  `[12]`=RTMP_AllocateRxPacketBuffer 返回的缓冲 VA、`[24]`=缓冲长度、
  `[28]`=下一 desc。
- RX 缓冲：type≤1 的环每块 **0x6a4=1700B**，并在每块头部预填 16B RXD
  （buf[0..3]=DMA 地址、+6=长度低字节、+7=0x40|长度高字节）。
- type==5 的环在 `asic_cap & 0x2000` 时打 `ring+0x1f=1` 标记（疑似 cmd/ exempt 环）。
- 环类型分派：类型 1 → `hif_ctrl+0x88`，类型 3 → `+0x8c`。

寄存器侧（base/len/cidx/didx）仍不在本函数内——它只建内存环，
`hif_set_WFDMA` 只拨使能位；**环寄存器编程在 multi_hif_entry_* 系
（下一步用带重定位的 dis 逐个解）**。

#### 6.5.1 MCU TX 真实通道（修正 6.2：buffer-mode 结论作废）

- `mt7916_init` 填 `[0xF0]=bufferModeCmdFill`，但 **`RtmpRaDevCtrlInit` 在
  `RtmpChipOpsHook` 之后调 `ChipOpsMCUHook`（0x1B8CA4，条件 chip_cap+68 bit2），
  把 `[0xF0]` 覆盖为 `AndesSendCmdMsg`**——bufferModeCmdFill 是覆盖前的初值，
  正常运行是死代码。
- 最终链：`MtCmd* → AndesInitCmdMsg/AppendCmdMsg → chip_cmd_tx → chip_ops[0xF0]
  = AndesSendCmdMsg(priv, skb[, r2 遗留])`。
- `AndesSendCmdMsg`(0x1B9B18)：cmd=msg[4]，bit2=等回包；能力字
  `flags = *(priv+0xEAF200)`：bit24=固件已载可走 WFDMA（先查
  `IsStopingPdma(priv+0xF0FD84)`）、bit8→路径C、bit29→路径D、bit24=0→拒发。
  发送本身=入队（`AndesQueueTailCmdMsg`，队列头 priv+0xEFEF28）+ tasklet
  （`AndesCtrlInit` 0x1B98AC 用 `tasklet_init` 注册 **`AndesCmdMsgBh`**，并清
  bit24 直到固件下载完成）。
- BH `AndesCmdMsgBh`(0x1B9700)：出队每条消息调
  `hif_rx_event_process(priv, msg)`——**发送+收事件合一在 HIF 层**
  （名字带 rx 是障眼法）。
- `dbg_ut_wmcu_send`(0x2b8410) 只是对 tr 统计结构 printk 的诊断函数，非通道 ✓。
- cb[0xB00]=alloc msg、cb[0xB0C]=rx event process（cb = `*(priv+0xF0002B0)`，
  即 chip_ops@+0xD20 所在的同一控制块）；这两槽的填充者未解（无直接 str，
  疑 memcpy 模板，下轮钉）。
- **基地址体系两套，别混**：`hc_get_hif_ctrl` = priv+0x9F8（io-ops/multi_hif
  层，`pci_core_ops_register` 填 [0x00..0x9C]）；cb = `*(priv+0xF0002B0)`
  （chip_ops 层）。

#### 6.5.2 fw 子表三槽全解（任务②闭合）

`mt_fwdl_hook_init`(0x1D6FBC) 填表，**表基址 = priv+0xEEE000**（指针存
`chip_cap+0x110`，即 `mt_load_fw` 里 `ldr r9,[chip_cap,#272]` 的来源），按
chip_cap 版本字段选择：

| 槽 | 函数（按 chip_cap 字段） |
|---|---|
| `[0xFA8]` | load_fw_v1 / load_fw_v2_compressimg（chip_cap+0x118：0→v1、1→v2） |
| `[0xFB0]` | parse_fw_v1 / v2 / v3（chip_cap+0x120：0/1/2） |
| `[0xFB4]` | parse_patch_v1 / v2 |
| `[0xFB8]` | ctrl_fw_state_v2 |
| `[0xFAC]` | load_patch_v1（chip_cap+0x114==0 时） |

与 `mt_load_fw` 实际调用序列（0xFB8→0xFB8→0xFB0→0xFA8）完全对上。
doc 14 §1 记作"chip_ops->[0xFA8]"是简写，**基址是 fw 子表**。

#### 6.5.3 环寄存器布局（任务①主体闭合；每环具体地址待 .data 模板）

`dump_dma_tx_ring_info`/`dump_dma_rx_ring_info`(0x2FE8/0x3094) 实证环寄存器
块为 **4 个连续 32 位寄存器**：

```
reg+0  = BASE（描述符数组总线地址）
reg+4  = CNT（环深度）
reg+8  = CPU_IDX（host 侧游标 cidx）
reg+12 = DMA_IDX（硬件游标 didx）
TX 空闲 = cidx − didx（模 CNT）；RX 待收 = didx − cidx − 1（模 CNT）
```

`mt_asic_init_txrx_ring`(0x1E0270) 印证：RX 环块基址存 ring->0x2C、TX 环
块基址存 ring->0x4C（`hif_io_write32` 三连：BASE、CPU_IDX=0、CNT=CNT 值取
`ring+0x5A` u16）；TX 初始化顺序 BASE/CNT/CPU_IDX=0（个别 val 映射待核）。
**每环的 reg_base 具体值（0x1802_4xxx/5xxx 表）在 multi_hif entry 的
.data 常量模板里**，`mt7916_hif_pci_data_ring_assign`(0x19411C) 只按
id=0x00138430 找入口挂指针，不碰寄存器——下轮 dump .data 的环配置模板钉地址。
